## Known residuals

- `focusMove` nulls the selection anchor unconditionally, so in principle a keydown
  landing on a focused cell mid-pointer-drag could stop the drag extending. Reaching it
  requires defeating `onCellPointerDown`'s `preventDefault()`, which suppresses
  focus-on-mousedown, so no reachable trigger is known. No data consequence.
- Resilience to a corrupt `settings.json` is untested: `SettingsStore.Load` throws
  uncaught, so every endpoint would 500 with no recovery path. Pre-existing, and more
  consequential for a server than it was for the WPF screen it came from.
- The real `PaceClientFactory` and `CredentialTokenSource` have no test coverage; they
  are always faked so tests stay off the developer's real Credential Manager.
- `ParseWorkLogs`'s type-mismatch fallbacks silently coerce to 0 or empty. Same risk
  class as the open live-API check rather than independent of it.
- `MonthView.tsx` is ~300 lines carrying fetch, selection wiring and dialog
  orchestration alongside grid rendering. Not unmaintainable, but it should not take
  another feature without extracting the handlers or the grid JSX.

## The verification gap worth acting on

The web reviewer's structural finding: across 16 task reviews and their fix rounds,
nothing caught `lang="en"` on an all-Swedish UI, missing status words in day-cell
accessible names, absent live regions on failure banners, or a keyboard-only selection
bug that silently dropped days. All four were found only at the end, and all four were
fixed. The cause was method, not diligence: verification leaned on code tracing and
mouse-driven Testing Library interactions, and never exercised the keyboard and
screen-reader path end to end. One manual NVDA or Narrator pass over the calendar, a
failed load and one dialog would likely have surfaced all of them at once.

The C# reviewer's complementary finding: the app validates its own API surface
thoroughly — every input path has a guard and a test — but its resilience to bad data
arriving from outside its control is thin, and the one gate meant to close that (the
live 7Pace check) covers only the 7Pace side, not the local settings file.
